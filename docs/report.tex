\begin{center}
{\Large\bfseries Nemotron activation extraction}\par\vspace{2pt}
{\small Output speed and numerical agreement --- Antonio Lobo-Santos, DFKI --- 21 October 2026}
\end{center}

On one H200, the package saves activations at \textbf{5,535 tokens/s versus 3,930 for Transformers} at batch 64 (\textbf{1.41$\times$}). The sibling fill writer reaches \textbf{24,079 tokens/s} (\textbf{6.13$\times$}). We assess both output speed and numerical agreement of these activations: the model's internal vectors at selected recording points, or sites.

\textbf{Output speed.} We record 18 sites across six hook types in the official \href{https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16}{Nemotron 3 Nano BF16 checkpoint}. For a consistent comparison, each table entry processes the same 131,072 frozen English tokens in 512-token sequences on the same physical H200, after two warm-up batches. Output tokens/s counts input tokens whose activations are saved at all sites, including capture, transfer, buffer waits and completed writes. Loading, warm-up and numerical comparison are excluded. GPU forward speed separately measures model execution.

The package peaks at 6,406 output tokens/s across five batch sizes (8--128): 1.84$\times$ Transformers at batch 8. At batch 64, however, similar vLLM forward speeds yield markedly different output rates. Model execution speed alone therefore does not predict extraction throughput. These complete paths differ in publication and finite-value checks. All use eager BF16 execution; vLLM enables chunked prefill and automatic KV-cache sizing. Requested batch sizes limit admission; actual forward batches may be smaller.

\textbf{Numerical agreement.} To assess output agreement, we compare each vLLM path with Transformers (HF/PyTorch). Cosine measures directional alignment; relative L2 measures error relative to the reference magnitude. Each site must achieve mean cosine $\geq0.9999$, minimum token cosine $\geq0.9990$, and relative L2 $\leq0.02$. All three paths pass only 3/18 sites. Similarly, a BF16 sample of 16,384 tokens per language gives mean site cosine 0.999002 (English), 0.998623 (German) and 0.998701 (Spanish). High averages therefore conceal token outliers. Normalised MSE equals relative L2 squared.

\textbf{Explaining the differences.} To separate local arithmetic error from upstream differences, we replay individual operations with original weights and identical saved 2,048-token inputs. On RTX A6000, PyTorch and vLLM mixture-of-experts (MoE) operations share a runtime, FP32 routing, top-six selection among 128 experts and normalised weights scaled by 2.5. Both use IEEE settings, disable reduced BF16 reductions and share the selector to align ties. Across layers 1, 27 and 51, mean cosine rises from 0.9999948--0.9999995 in BF16 to 1.0000000 in FP32 (rounded); worst-token cosine rises from 0.9999882 to 0.9999993. Maximum relative L2 falls from 0.00365 to $1.05\times10^{-6}$; all 16 comparisons pass. Likewise, the first Mamba block on RTX 3090 gives relative L2 0.00291 in BF16 and $1.18\times10^{-7}$ in FP32. IEEE flags alone leave its BF16 output unchanged.

At cosine $<0.999$, token counts fall from 28 to 0, 1,005 to 885 and 139 to 96, respectively. Among tokens recovered above 0.99, single-expert swaps account for 4, 193 and 3 recoveries. Defining a near tie as a corrected sixth/seventh score gap $\leq0.001$ gives only 3, 23 and 0 recoveries. Selection therefore explains some discrepancies, particularly at layer 1, while deeper errors extend beyond near ties. These effects interact with upstream error and cannot be added across layers.

\textbf{Scope and evidence.} The output rates describe package 1.0.0 in BF16; the FP32 results validate individual operations. Full-model FP32 agreement and output speed remain unmeasured.
